# Security Policy

## Scope
This policy covers the published documentation and any future safe, defensive components. The original executable assessment source is not included in this documentation release.

## Reporting
Use GitHub's private vulnerability reporting feature if enabled. Otherwise, open a minimal issue that does not disclose exploit details, credentials, tokens, personal information, or sensitive target data. Ask the maintainer for a private reporting channel.

Include a concise description and potential impact, affected file/component and version/commit, safe minimal reproduction steps in a local test environment, and suggested remediation if known.

## Responsible disclosure
Do not access or modify other users' data, disrupt services, or test third-party systems while investigating. Obtain explicit authorization and use isolated test environments. Allow maintainers reasonable time to investigate and prepare a fix before public disclosure.

## Secrets
Never commit passwords, API keys, session cookies, private keys, access tokens, or real personal data. Revoke and rotate any secret that may have been exposed.
